IAM Lens privacy policy

Last updated: 22 November 2026

IAM Lens has no analytics, no tracking and no remote code. If you sign in, your Google data is read directly by your browser, stored only on your device, and never sent to the developer. Signing out deletes it.

What IAM Lens is

IAM Lens is a browser extension that looks up Google Cloud IAM roles and permissions. It is developed by Ranger7899 and is not affiliated with or endorsed by Google.

No analytics, no tracking, no remote code

The extension does not collect analytics or telemetry, does not use advertising or tracking identifiers, and does not send your searches anywhere. All code that runs is shipped inside the extension package. It never downloads or runs code from a remote server.

Predefined roles snapshot

The list of Google Cloud predefined roles and permissions is bundled with the extension and refreshed periodically by downloading a public data file (the snapshot) from the IAM Lens website (iamlens.vaultline.cloud, hosted on GitHub Pages). This is a plain request for a public file. It contains no information about you beyond what any web request normally exposes to the host, such as your IP address, which GitHub handles under its own privacy statement.

Optional sign-in and custom roles

Signing in with Google is optional and is only needed if you want to see your own custom roles. Without signing in, IAM Lens does not contact any Google API and accesses no Google user data.

Google user data IAM Lens accesses

After you sign in, IAM Lens automatically looks up every project and organization your Google account can access, and then fetches the custom roles defined on each of them. You do not choose projects one by one. The data accessed is:

  • Project and organization IDs and display names, from the Cloud Resource Manager API (project and organization search).
  • Custom role definitions of those projects and organizations, from the Cloud IAM API (roles.list): role name, title, description, launch stage, whether it is deleted, and its list of permissions.
  • The OAuth access token that Google issues when you sign in, used only to authorize those requests.
  • Email address and profile: not collected. IAM Lens does not request any email, profile or OpenID scope, does not read your name or email address, and does not call any user-info endpoint.

When IAM Lens contacts Google

These requests are made only while you are signed in, and only:

  • right after you sign in on the options page;
  • when you open the side panel and more than 1 hour has passed since the last sync (or there has been no sync yet);
  • every hour while the side panel stays open;
  • when you press the refresh button.

If the access token has expired, IAM Lens renews it silently without showing a window. If that is not possible it asks you to sign in again; it never opens a sign-in window on its own. IAM Lens does not run any sync while the side panel is closed.

Scopes requested and why

IAM Lens requests two Google OAuth scopes:

  • https://www.googleapis.com/auth/iam: needed by the Cloud IAM API to list custom roles, which rejects read-only access. Google words it as “Manage your IAM policies”, but IAM Lens only uses it to read role definitions.
  • https://www.googleapis.com/auth/cloud-platform.read-only: needed to search the projects and organizations you can access, so their custom roles can be found.

IAM Lens makes only read (HTTP GET) requests to Google APIs. It never creates, changes or deletes any role, policy, project or other resource.

How your data is used, stored and shared

  • Google user data is used only to show you your custom roles inside IAM Lens (searching, listing and comparing roles and permissions).
  • Sign-in uses Chrome's built-in chrome.identity.getAuthToken with the Google account signed in to your Chrome profile. Chrome itself caches the OAuth access token. IAM Lens also keeps a copy in chrome.storage.session, which is held in memory only and is cleared when you close the browser.
  • The custom roles, and the IDs and display names of your projects and organizations, are stored locally in your browser in IndexedDB. They are not synced to your Google account and not uploaded anywhere.
  • Your requests go directly from your browser to Google (Google sign-in, the Cloud Resource Manager API and the Cloud IAM API). Nothing is sent to the developer or to any other server or third party, and no human reads your data.
  • There is no analytics, no advertising, no tracking and no remote code. Google user data is not used for advertising or sold.

Deleting your data

  • Sign out & clear (options page) revokes the access token with Google, removes it from Chrome's token cache and from the extension, and deletes all stored custom roles and the stored list of projects and organizations.
  • Removing the extension deletes everything it stored in your browser.
  • You can also revoke IAM Lens's access at any time in your Google Account permissions.

Google API Services User Data Policy

IAM Lens's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Specifically, data received from Google APIs is used only to provide the user-facing custom-role lookup features, is not transferred to others, is not used for advertising, and is not read by humans.

Permissions

The extension requests only the browser permissions it needs: side panel, local storage, scheduled alarms (for snapshot refresh), unlimited local storage (for the roles database), and context menu. The identity permission and access to googleapis.com are optional and are requested only when you choose to sign in.

Children

IAM Lens is a developer tool and is not directed at children.

Changes to this policy
